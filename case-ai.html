Problem

The Promotion Engine serves a growing pool of users across countries and brand requires from each user an increasing time spent defining the promotion and or campaigns which requires that the procedure of definition itself  needs to be fast and effective. Given a first analysis based on extracted analytics data, to understand the current AS-IS situation it was clear that several steps were required to define either a promotion or campaign. This process was time consuming (time spent into filling the form around 25min) and error prone and this could be just going worse 

Approach

Conducted A/B test to measure both speed and correctness, not just user preference:

  • Same task, two modes: involved users built the same promotion manually and with AI. Users involved were experts and new to the system. 
  • Multiple evidence sources: traced out event logs per session, mode and user type and validated those using a  post-test questionnaire and video recordings. 
  • Where the friction lives: broke time down by section and mapped real user paths, revealing a different optimal user flow.

Solution

Defined a business case for IT with a clear, conditional recommendation:

  • AI as primary mode, with manual creation kept as fallback.
  • Introducing UX-UI updates: in order to make the manual process as smooth as possible  
  • Second test round with a larger, more balanced sample before committing rollout budget.

Outcome and results

Turned a A/B test into a data-backed business case for making an AI assistant the primary way to create promotions.

AI cut creation time by 45% and the validation error rate from 92% to 8%. The real issue was domain understanding first and then also slowness caused by UX-UI ineffencies. The sample was smaller than planned, so results are to be validated with an addition bigger user pool. .
